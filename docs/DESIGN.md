# DESIGN — 디자인 시스템 (보고서 · GUI 공용)

토큰의 단일 출처는 `src/flightqa/theme/tokens.py` 다. 보고서 CSS(`css_root()`)와 GUI QSS 가 같은 값을 읽는다.
원칙 (CLAUDE.md §6): 첫인상에서 유료 도구로 보일 것, 기본 Qt/브라우저 스타일을 노출하지 않을 것, 오프라인에서 완결될 것.

## 2. 타이포

- 글꼴: `Segoe UI`, `Malgun Gothic` (Windows) → `-apple-system`, `Apple SD Gothic Neo` (macOS) → Noto Sans KR → sans-serif. 웹폰트·CDN 없음.
- 숫자는 `font-variant-numeric: tabular-nums` 로 열이 맞게.
- 크기 5 단계: xs 11 · sm 12 · md 14 (본문) · lg 18 · xl 26 px. 줄간격 1.5.
- 제목 굵기 650, 자간 −0.01em.

## 3. 간격·모양

- 4 px 그리드 (`--sp`). 카드 안쪽 여백 12 px, 섹션 간격 32 px.
- 모서리 반경 2 단계: 6 px (카드·버튼·입력), 12 px (패널·비행 섹션).
- 그림자 2 단계: `--shadow1` (카드), `--shadow2` (떠 있는 요소).
- 아이콘: 단일 세트(Lucide, ISC 라이선스)의 선형 아이콘만. 보고서는 인라인 SVG.

## 4. 상호작용

- 모든 버튼: hover 배경 `--bg3`, focus-visible 2 px `--focus` 링, disabled 50 % 불투명.
- 전환 160 ms (`--motion`), 과하지 않게. 애니메이션은 상태 변화에만.
- 보고서 툴바: 테마 토글 (localStorage 기억), 인쇄. 스크롤 시 고정.

## 5. 보고서 레이아웃

1. 표지: 제목·부제, 폴더·센서·촬영일·캡처·비행·생성 시각, 큰 판정 배지.
2. 종합 판정: 상태색 전체 테두리, 짧은 결론(`headline`, 예 "재비행 검토 필요") + 근거 한 줄(`headline_detail`, 예 "게이트 항목 실패 1건: RTK 고정해(Fix) 캡처 비율"), 경고 박스, 권고 조치 목록(`action_items`: 상태색 점 · 항목명 · 비행/그룹/판정 메타 · 문장별 줄바꿈). "— " 로 이어 붙인 긴 헤드라인과 `[F1_…]` 접두 문자열은 쓰지 않는다 (CLI 텍스트 `next_actions` 에만 남는다).
3. 비행 섹션 (비행마다): 요약 카드 10 개 → 궤적·커버리지 지도 2 장 (왼쪽 UTM m, 오른쪽 EPSG:4326 위경도; 휠 확대·드래그 이동·더블클릭 초기화, 두 지도 확대 범위 연동, 위성 배경 버튼) → 항목별 상세(그룹마다 표 하나: 상태 배지·그룹명·개수 머리줄 + 판정/항목/측정값/근거 표, 표 사이 16 px) → 시계열 6 종 (2 열) → 조사 라인 표 → 대표 캡처 썸네일.
4. 제외 파일·경고 (데이터셋 단위 판정 표 + 제외 목록).
5. 부록: 소프트웨어 버전·소요 시간, 적용 설정, 원본 태그 샘플 (접힘).

반응형: 760 px 이하에서 차트 1 열, 표는 `overflow-x: auto` 컨테이너 안에서만 스크롤. 1280/800/400 px 에서 가로 오버플로 0 을 테스트로 고정한다 (`tests/test_report.py`).

차트 범례 (2026-09-11 개정): Plotly 범례를 끄고 템플릿 JS 가 **HTML 범례**(`.chart-legend`, 트레이스 이름·색·선 종류의 SVG 스와치)를 그래프 위 중앙에 그린다. 항목 폭을 재서 한 줄에 다 들어가면 n 열, 아니면 2·3 열 대칭 격자(`grid-template-columns: repeat(cols, max-content)`, `justify-content: center`)로 둔다 — Plotly 범례는 왼쪽부터 채워 "3+1" 이 되고 fraction 폭은 칸 안에서 왼쪽 정렬이라 중앙 정렬이 불가능했기 때문. 클릭하면 트레이스를 켜고 끈다(`Plotly.restyle visible`). 인쇄에서는 HTML 범례가 그대로 인쇄되고 차트 PNG 에는 범례가 없다. 창 크기가 바뀌면 열 수를 다시 계산한다. 시계열 6 종은 높이를 280 px 로 통일해 2 열 격자의 행 높이가 맞는다.

표 정렬: 열 제목은 모두 가운데. 셀은 근거(`td.txt`)·경로만 왼쪽, 나머지(판정 배지·항목·측정값·조사 라인 전부)는 가운데. `word-break: keep-all` 로 한국어 어절 단위 줄바꿈. 근거 열은 글머리표 목록(`.td-list`): `•` 근거, `→` 권고 조치(브랜드색), `▸ 기준:` (옅은 작은 글씨) — 문장은 마침표 직후에서 줄을 바꾼다(`core/textfmt.split_sentences`). 그룹은 표 자체를 나눈다(`.group`, `data-status`): 머리줄에 상태 배지·그룹명(h4 15 px)·"N 항목 · 실패 x · 주의 y", 왼쪽 4 px 상태색 띠. 비행 섹션 제목의 상태는 배지 대신 제목 앞 색 점으로 표시해 판정 개수 배지("실패 6")와 중복되지 않게 한다.

상태 클래스 규칙: `.pass/.warn/.fail/.na` 는 글자색+옅은 배경을 함께 바꾸는 **배지 전용** 클래스다. 블록(판정 카드·그룹 표)에는 절대 붙이지 않고 `data-status="…"` 속성 선택자로 테두리·띠 색만 바꾼다 (블록에 붙이면 안의 모든 글자가 상태색으로 물든다 — 2026-09-11 PDF 에서 실측).

소제목(h3) 문법: 브랜드색 4×16 px 세로 막대 + 16 px 굵은 제목(본문색) + 옅은 보조 설명(`.sub`) + 아래 헤어라인. GUI 의 `section()` 도 같은 모양이라 화면·보고서·PDF 에서 소제목이 같은 위계로 읽힌다. 요약 카드는 보조 줄이 비어도 자리를 유지해(`&nbsp;`) 높이가 나란히 같다.

궤적 지도 색: 궤적 선 진한 파랑 `#1E40AF` 2 px, 플래그 없는 캡처 마커 밝은 파랑 `#3B82F6`(흰 외곽선 0.8 px, 위성 배경 위에서도 보이게), 경고·실패·지상 마커는 상태색. 지도 위 범례 칩의 "정상" 도 같은 파랑. 커버리지는 주황 외곽선 `#EA580C` 1.5 px + 16 % 채움, 커버리지 공백은 빨강 `#DC2626` 점선 + 35 % 채움 — 위성 배경(초록·갈색)과 파란 궤적 어느 쪽과도 겹치지 않는 색.

차트 컨테이너: `.chart` 높이를 JS 가 `layout.height` 로 고정하고 `figure`/`.chart` 는 `overflow: hidden`. 창 크기 변화 없이 컨테이너만 바뀌는 경우(GUI 에서 숨겨진 웹뷰 탭이 보이게 될 때)를 위해 `.page` 에 `ResizeObserver` 를 걸어 `Plotly.Plots.resize` 와 범례 재배치를 한다. 축 눈금 숫자와 축선 사이는 x·y(·y2) 모두 `ticklabelstandoff: 6`.

스타일 톤 (Apple 계열): 시스템 글꼴 우선(`-apple-system, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", "Pretendard", "Malgun Gothic"`), 바탕 `#F5F5F7`, 헤어라인 경계 `rgba(0,0,0,.06)`, 둥글기 12/14/18 px, 옅은 2 단 그림자, 알약형 버튼·배지, 얇은 대문자 소제목. 색 토큰은 공용(`theme/tokens.py`)을 그대로 쓰고 보고서 CSS 에서 바탕·경계·둥글기·그림자·글꼴만 덧씌운다(GUI QSS 에 영향 없음).

인쇄·PDF (2026-09-11 개정): A4 세로, 12 mm 여백(내용 폭 186 mm = 703 px), 항상 라이트 팔레트. 화면과 같은 구조를 유지하되 시계열은 1 열(전폭), 지도·카드는 2 열/5 열로 둔다. 비행 섹션은 새 페이지에서 시작한다(`break-before: page`) — 표지+종합 판정이 1 쪽, 비행 요약·지도가 2 쪽부터.
차트는 로드 직후 브라우저 안에서 인쇄 폭에 맞춰 다시 배치한 **정적 PNG(3 배 해상도)** 로 구워 두고(`Plotly.toImage`, `figure.has-print`) 인쇄 시 이 이미지를 쓴다. 따라서 Ctrl+P, 인쇄 버튼, GUI/CLI 의 PDF(QtWebEngine `printToPdf`, `__flightqa_print_ready` 대기) 결과가 같다. 강제 페이지 나눔은 두지 않고 카드 묶음·그림·표 행·썸네일만 `break-inside: avoid`, 제목·그림 설명은 `break-after: avoid`. 표 머리글은 sticky 를 쓰지 않는다 (`overflow-x: auto` 컨테이너 안에서 머리글이 44 px 내려앉아 첫 행을 가리는 버그가 있었다). 부록의 설정 JSON 은 2 단 9 px, 원본 태그 샘플은 인쇄에서 뺀다.

## 6. GUI (M4 에서 구현)

같은 토큰을 QSS 로 내보낸다. 화면 흐름은 CLAUDE.md §6.3: 홈(드롭존·최근 목록) → 분석(단계 진행률·로그) → 결과(판정 헤더·항목 카드·미니맵) → 설정.
고 DPI 는 Qt 의 논리 픽셀을 그대로 쓰고, 아이콘은 SVG 로 둔다.

결과 화면 (2026-09-11 개정):
- 판정 카드: 상태색 2 px 전체 테두리(`QFrame[role=verdict]`), 배지 + 짧은 결론(20 px) + 근거 한 줄 + 메타 + "권고 조치" 섹션(리치 텍스트 표: 상태색 점 · 항목명 · 비행/그룹/판정 · 문장별 줄바꿈, 6 건까지 표시).
- 소제목은 모두 `common.section()` (브랜드색 막대 + 16 px 굵은 제목 + 보조 설명 + 헤어라인). 요약 카드(`StatCard`)는 보조 줄을 항상 두고, 그룹 카드는 항상 3 줄(제목·개수·대표 항목 또는 "모든 항목 기준 충족").
- 상세 탭: 왼쪽 비행 목록은 가로 스크롤 없이(비행 열 stretch, 행 높이 44 px 고정), 오른쪽은 그룹마다 표 하나(`GroupBlock` = 머리줄 + `AutoHeightTable`, 표 사이 16 px, 바깥 스크롤 하나). 판정 배지는 셀 한가운데 고정 크기, 모든 열 가운데 정렬, 근거 열만 왼쪽이며 `RichTextDelegate` 가 글머리표(• 근거 / → 권고 조치 / ▸ 기준) 리치 텍스트를 그리고 열 너비에 맞춰 행 높이를 잰다. 표는 `NoFocus` 로 현재 셀 강조를 없애고, hover 는 브랜드색 8 %(다크 14 %), 선택은 `brand_soft`.
- 보고서 탭이 보이게 되면 웹뷰에 `resize` 이벤트를 보내 차트를 컨테이너에 다시 맞춘다 (템플릿의 `ResizeObserver` 와 이중 안전장치).
- 결과 화면은 **페이지 하나가 스크롤**된다(`ResultsPage.page_scroll`): 판정 카드·버튼·탭 내용이 함께 내려가고, 요약의 카드 격자와 상세의 그룹 표는 안쪽 스크롤 없이 내용 높이만큼 늘어난다. 탭은 `Tabs`(QTabBar + 현재 페이지 크기만 보고하는 스택)로, 보이지 않는 페이지는 `Ignored` 크기 정책이라 높이에 끼어들지 않는다.
- 보고서 탭의 웹뷰는 **창(뷰포트) 높이**로 두고 탭을 열면 웹뷰 위가 창 위에 오도록 바깥을 자동 스크롤한다. 문서 높이(1 만 px 이상)만큼 웹뷰를 키우면 Chromium 이 아래쪽을 그리지 않아 쓰지 않는다. 휠은 이어진다: 아래로 굴릴 때 바깥이 끝이 아니면 바깥이 먼저 내려가고(`_WebWheelForward`), 보고서 맨 위에서 위로 굴리면 QtWebEngine 이 처리 못 한 휠을 부모로 넘겨 바깥이 올라간다.
- 웹뷰 URL 에 `#embedded&theme=dark|light` 를 붙여 보고서가 GUI 테마를 따르고(`window.__flightqa_setTheme`, 테마 토글 시 호출) 페이지의 테마 버튼은 숨긴다.
- 홈의 최근 폴더 행: 아이콘 · 이름/메타 · 판정 배지 · [다시 분석][목록에서 제거] 아이콘 버튼. 더블클릭은 지난 결과 열기(결과가 없으면 다시 분석할지 묻는다), 우클릭 메뉴는 다시 분석 / 지난 결과 열기 / 목록에서 제거 세 가지뿐(글자 선택 메뉴 없음). 다시 분석·제거·비우기는 확인 대화상자를 거친다.

## 7. 문구 규칙 (근거·권고 조치·용어)

판정 항목의 세 줄은 역할이 다르고 모두 **개조식**이다 (2026-10-08, 사용자 지적: "→" 줄만 "~느슨하다." 같은 서술형이라 이질감).

- `•` 근거(`reason`): 측정값과 비교 대상. 명사형 종결, 마침표 없음. 예 "1,520 / 1,540 장 정렬, 미정렬 20장".
- `→` 권고 조치(`next_action`): **첫 줄은 조치**(명사형, "확인·재비행·재실행·검토"), 조치가 여럿이면 가운뎃점(·)으로 잇는다. 둘째 줄은 선택이며 `영향:`(그대로 두면 생기는 결과) 또는 `원인:`(의심되는 원인) 접두로 시작한다. 줄 구분은 문자열 안의 줄바꿈이며 `core/textfmt.split_sentences` 가 줄바꿈과 마침표를 경계로 나눈다. 서술형 종결("~한다", "~있다")과 마침표는 쓰지 않는다. 예: "Gradual Selection(Reprojection Error)으로 오차 큰 타이포인트 제거 후 Optimize Cameras 재실행 / 영향: 재투영 오차가 크면 정합 정밀도 저하".
- `▸` 기준(`threshold`): "WARN ≥ …, FAIL ≥ …" 꼴.

표 머리글과 섹션 이름은 "근거 / 권고 조치", "권고 조치"(보고서 종합 절·GUI 판정 카드·CLI). "다음 행동", "권고 행동" 은 쓰지 않는다.
